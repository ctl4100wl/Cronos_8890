# Cronos G930X / KernelSU Next

Target: **Exynos Galaxy S7 flat G930F/S/L/K**, `herolte`, **OneUI Q**.
Not for S7 Edge, Note7/FE, Snapdragon S7, stock Oreo, or arbitrary AOSP ROMs.

This build follows `cronos.sh`: concatenate `exynos8890_defconfig`,
`hero_defconfig`, `oneui_defconfig`, `cronos_defconfig`, in that order; use
`exynos8890_Oneui.dtsi`; enable the Q hall sensor reversal. KernelSU Next is
built in with manual hooks, KPROBES disabled, KSU debug disabled, and SELinux
enforcing by default. Stock clocks, thermal limits, N935F interactive governor,
and DVFS are retained following the creator's V8 stability notes. No overclock
or undervolt is added. This is device-specific configuration, not a claim of
measured performance improvements.

## Installer provenance

The supplied `CronosKernel-V8.1-20231231-KernelSU.zip` uses corsicanu's Floyd
installer (CC BY-NC-SA 4.0). Its `ramdisk.img`, `magiskboot`, `busybox`, and
LICENSE match the existing `Cronos/kernelzip` assets byte-for-byte. The
packager verifies their SHA-256 hashes before producing either installer.
`installer-g930x/upstream-update-binary` preserves the supplied original script.

The default **Floyd ZIP** adapts that installer to G930F/S/L/K only. It builds
from the same clean boot template, replaces the kernel and Samsung DTB `extra`
field, and performs one BOOT write after repacking and checking partition size.
It omits the other models' binary patches. Unlike the original script, it does
not flash the blank template to BOOT before repacking. Failures abort explicitly.

The **AnyKernel3 ZIP** uses the separately configured
`anykernel3/anykernel.sh`: Exynos BOOT path, non-A/B, herolte checks, Android 10,
no modules, no Magisk preservation, the same clean boot template, and the
Samsung DT table as `dt` (AK3 maps this to boot `extra`). It contains no example
Tuna device checks or sample ramdisk tweaks.

Both packages replace previous ramdisk customizations, including Magisk.
Use one package, not both. Back up BOOT in recovery before testing. Hardware
boot, root grants, modules, Wi-Fi, calls, camera, sleep and recovery still need
testing on a real G930 device. Compilation does not establish device safety.

## Build

GitHub Actions: `Cronos G930X KernelSU Next`. Push/PR triggers and manual
`workflow_dispatch` are provided. Download the artifact; the inner `*-Floyd.zip`
and `*-AnyKernel3.zip` are the flashable packages. The artifact also includes
the resolved config, build log, manifest and SHA256SUMS.

Locally, use the pinned Linaro 4.9.4 compiler and run:

```sh
CROSS_COMPILE=/path/to/linaro/bin/aarch64-linux-gnu- bash scripts/ci/build-g930x.sh
```

Python 3, make, gcc, bc, flex, bison, OpenSSL and ELF development headers are
required (plus ccache, or set `USE_CCACHE=0`). Dependencies are pinned in the workflow and packager. KernelSU and
WireGuard no longer download or replace source from inside Kbuild parsing.

## Sources and compatibility changes

- Base: `ctl4100wl/Cronos_8890` `cronos_ksu`, `89bd34c780ee321553aaac86f5deca4eb294d4b2`.
- KernelSU Next: tag `v3.4.0-legacy`, `8af3d4fec33be32fa5d3f8dae4f380fac45bf2cd`.
  Tag `v3.4.0-legacy`; version 33294 = 30000 + 3005 commits + upstream legacy offset 289.
  This is a legacy snapshot, not a claim to be the mainline v3.4.0 driver.
  Use a compatible KernelSU Next legacy Manager; original KernelSU Manager is
  not the matching client. The Manager is not silently installed by recovery.
- AnyKernel3: `osm0sis/AnyKernel3`, `41f04bdb4ee30a44e429c2c1131d5e8bb32b15f1`.
- Compiler: `ryan-andri/aarch64-linaro-linux-gnu-4.9`, `0d26f997569c21965380406733378e3546279f18`.
- WireGuard: `WireGuard/wireguard-linux-compat` v1.0.20220627,
  `18fbcd68a35a892527345dc5679d0b2d860ee004`.

The Next sources and UAPI are vendored under `drivers/kernelsu`. Cronos-specific
changes use the existing old file I/O compatibility wrappers, old filldir and
compat-task APIs, READ_ONCE/WRITE_ONCE feature flags instead of newer static-key
wrappers, and `/proc/1/ns/mnt` with KernelSU credentials where `ns_get_path`
is unavailable. The SELinux avtab uses Cronos's backported pointer-array layout,
while the other policy tables keep their flex-array layout. The reboot supercall
hook is added before the normal reboot permission check; Next validates its
own commands. Existing exec/access/stat/read/input manual hooks are retained.
Required namespace, seccomp and SELinux helper backports are committed as source
rather than generated by sed while compiling. Original licenses are retained.

Developer notes: https://github.com/ananjaser1211/Cronos_8890/releases
Next legacy source: https://github.com/KernelSU-Next/KernelSU-Next/tree/legacy

The optional Next `nuke_ext4_sysfs` ioctl returns `-EOPNOTSUPP` on this 3.18
tree; its standalone ext4 unregister helper is absent. Root and module mounting
do not require it. SUSFS is not integrated in this build.

## GitHub compiler cache

Install ccache explicitly and cache only `.ccache`, not source, compiler binaries,
or credentials. Restore/save use GitHub's official `actions/cache` split actions.
Immutable keys identify OS, architecture, device, compiler revision, configuration
hash and source commit. Prefix restore keys seed a new commit from prior builds;
ccache still validates every compilation with compiler-content checks. Save runs
on non-cancelled failures too, so a late build/release failure does not discard
useful compiled objects. A 2 GiB compressed cache limits storage use. Statistics
are uploaded with artifacts. First runs and evicted/branch-inaccessible caches
are expected misses; builds work without a downloaded cache.

Kbuild wraps only C/C++ compilation with ccache: assembler, linker, archiver,
symbol and objcopy tools run directly, and CPP is wrapped only once. The local
build script requires ccache by default; `USE_CCACHE=0` explicitly disables it.

Reference: https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching

## Manager compatibility correction

Use the official v3.4.0 Manager **33294** (regular or spoofed); both use UAPI 4.
The kernel now uses the matching **v3.4.0-legacy tag**, not the newer legacy
branch tip. The first test build used branch tip b933b1f with UAPI 6; that was
incompatible with the v3.4.0 APK and caused its "Manager too low" warning.
The APK's literal `%1$d` / `%2$d` placeholders are an upstream warning-format
bug, not meaningful driver version values. Do not raise a version number to
bypass the check: `scripts/ci/check-manager-abi.py` compares actual ioctl and
structure ABIs against the official Manager headers before building.

Manager: https://github.com/KernelSU-Next/KernelSU-Next/releases/tag/v3.4.0
Matching legacy tag: https://github.com/KernelSU-Next/KernelSU-Next/tree/v3.4.0-legacy

## OneUI Q boot transition correction

The device report captured init failing to execute /data/adb/ksud with EACCES,
and a security_bounded_transition denial from u:r:init:s0 to u:r:ksu:s0.
Cronos's existing check_nnp_nosuid exception still resolved the original
KernelSU u:r:su:s0 domain. Resolve KernelSU Next's u:r:ksu:s0 instead, preserving
the existing init-only and exact-target checks. SELinux enforcing remains on.

The regression test compiles the actual shipped check_nnp_nosuid function
with mocked policy calls. It reproduces the old EACCES failure and verifies
init-to-ksu succeeds after the correction, unrelated transitions remain denied,
and CONFIG_KSU=n preserves the normal checks. This isolates the observed boot
denial; a physical full-reboot test is still needed to establish module startup.
